# Вариант №15 — Шлагбаум

Курсовой проект по ПМ.02 «Сопровождение и схемотехническое обслуживание интеллектуальных интегрированных систем».

## Назначение системы

Виртуальная система на Arduino Uno измеряет освещённость,
расстояние до автомобиля и состояние кнопки вызова.

При расстоянии меньше 30 см сервопривод открывает шлагбаум
на угол 90°, включается белый светодиод и формируется
событие THRESHOLD.

При возврате расстояния к 30 см и выше шлагбаум закрывается,
светодиод выключается и формируется событие NORMAL.

Освещённость и кнопка вызова записываются в журнал,
но не участвуют в условии открытия.

## Проект Wokwi

https://wokwi.com/projects/477932488285293569

## Входные данные

- Датчик 1: LDR, учебная шкала освещённости 0–100 %.
- Датчик 2: HC-SR04, расстояние 2–400 см.
- Датчик 3: ползунковый переключатель, имитирующий кнопку вызова.
- Исполнительное устройство: сервопривод.
- Индикатор: белый светодиод, заданный ток 20 мА.
- Резистор индикатора: 100 Ом, расчётный ток около 18 мА.
- Пауза между циклами опроса: 3 секунды.
- Порог события: расстояние меньше 30 см.

Шкала LDR вычисляется по учебной линейной формуле,
а не является физически откалиброванным процентом освещённости.

## Подключения Arduino

| Компонент | Вывод |
|---|---|
| LDR, AO | A0 |
| HC-SR04, TRIG | D3 |
| HC-SR04, ECHO | D4 |
| Белый светодиод через резистор | D5 |
| Средний контакт переключателя | D6 |
| Сигнал сервопривода | D9 |

Модули питаются от 5V и GND.
Переключатель замыкает D6 на GND; используется INPUT_PULLUP.
Значение s3=1 означает замкнутый переключатель.

## Структура проекта

- firmware/sketch.ino — программа Arduino.
- sim/diagram.json — схема Wokwi.
- data/log.txt — текущий журнал для загрузки.
- data/log_normal.txt — журнал штатного сценария.
- data/log_fault.txt — журнал проверки неисправности.
- db/schema.sql — создание таблиц.
- db/queries.sql — три контрольных запроса.
- db/variant.db — база SQLite.

- nodered/flow.json — экспорт потока Node-RED.
- docs/ — схема EasyEDA, BOM и скриншоты проверок.

## Формат журнала

DATA n=5 s1=24.44 s2=19.9 s3=0
EVENT n=5 type=THRESHOLD

n — номер измерения.
s1 — освещённость по учебной шкале.
s2 — расстояние в сантиметрах.
s3 — состояние кнопки вызова.

Дробные числа записываются через точку.
Журнал нужно копировать из Wokwi без перевода страницы.

В базе используется условное расчётное время t_s = n × 3.
Оно не является точной временной меткой: скетч использует delay().

## Порядок запуска

1. Открыть проект Wokwi и запустить симуляцию.
2. Изменить расстояние: 100 → 20 → 50 см.
   Между изменениями подождать несколько секунд.
3. Скопировать Serial Monitor в data/log.txt и сохранить в UTF-8.
4. Открыть командную строку и выполнить:

   cd /d C:\Users\clabo\kursovoy15
   node-red

5. Оставить командную строку открытой.
6. Открыть http://localhost:1880.
7. Если поток ещё не установлен, импортировать nodered/flow.json
   через Ctrl+I. Повторно импортировать уже установленный поток не нужно.
8. Нажать Deploy.
9. Нажать кнопку слева от узла «Загрузить лог».

В дальнейшем сохранение log.txt запускает автоматическую загрузку.

## Проверка базы

Из корня проекта выполнить:

"C:\tools\sqlite\sqlite3.exe\sqlite3.exe" -header -column db\variant.db ".read db/queries.sql"

Запросы выводят:
1. Десять последних показаний.
2. Минимум, среднее и максимум каждого датчика.
3. Все события по порядку.

## Проверки

Штатный журнал содержит 12 циклов:
- 36 записей в readings;
- 2 события в events;
- THRESHOLD при n=5;
- NORMAL при n=7.

Для проверки FAULT используется строка:

DATA n=1 s1=999 s2=100.0 s3=0

Она вызывает событие:
FAULT — датчик s1 вне диапазона.

Для запуска теста нужно скопировать log_fault.txt в log.txt
и выполнить загрузку. После теста восстановить log.txt
из log_normal.txt и загрузить снова.

Каждая загрузка очищает readings и events и заполняет их
заново из текущего журнала. Поэтому повторная загрузка
того же файла не добавляет дубли.

Проект является учебной виртуальной моделью,
а не системой безопасного управления реальным шлагбаумом.
